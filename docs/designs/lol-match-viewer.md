## Problem Statement
LoL(리그 오브 레전드) e스포츠 경기를 확인할 수 있는 모바일 웹페이지. 어제/오늘/예정 경기를 시간순으로 훑어보되, 오늘 라이브로 진행 중인 경기는 정렬 순서와 무관하게 항상 최상단에서 바로 보여야 한다.

## What Makes This Cool
깔끔한 정보 밀도. 팀 로고·이름·스코어·시리즈 포맷(Bo3/Bo5)만으로 지금 무슨 일이 일어나고 있는지 한눈에 파악되는 것. OP.GG/네이버 e스포츠와 비슷한 카테고리지만, 군더더기 상태 라벨("종료", "경기 전") 없이 스코어 자체의 시각적 처리(승자 강조, 패자 회색 처리)로 상태를 전달한다.

## Constraints
- 데이터는 자체 백엔드에서 공급: `GET /matches?range={yesterday|today|upcoming}` (개발 환경 `http://localhost:9031`)
- 실시간 소켓 불필요 — 짧은 간격 폴링으로 충분
- 로그인/팀 상세/선수 상세는 스코프 밖. 경기 리스트 뷰어 하나만
- React Folder Structure(feature-based) + 기존 스택(Vite, TanStack Router/Query, Tailwind v4, shadcn) 그대로 사용

## Premises
1. 데이터 소스는 자체 백엔드 하나뿐 — 외부 API/크롤링 직접 연동은 이 프론트의 책임이 아니다. **합의됨**
2. 폴링 기반이면 충분하다 (소켓 불필요). **합의됨**
3. 경기 리스트 뷰어 단일 화면이 스코프다 (팀/선수 상세, 인증 제외). **합의됨**
4. 기존 세팅된 스택(shadcn/Tailwind v4/TanStack Router) 그대로 사용. **합의됨**

## Approaches Considered

### Approach A: 정적 탭 + 폴링 (선택됨)
어제/오늘/예정 3개 탭을 URL search param으로 관리. TanStack Query로 각 탭 진입 시 range별 fetch, 오늘 탭만 짧은 간격(예: 15초) 폴링으로 실시간성 확보.
- Effort: S · Risk: Low
- 장점: 가장 빠르게 완성, 유지보수 쉬움, 이미 설치된 TanStack Query와 자연스럽게 맞음
- 단점: 초 단위 실시간성은 아님 (폴링 간격만큼 지연)

### Approach B: 전역 상태(zustand) + 단일 fetch
세 범위 경기를 한 번에 다 불러와 zustand에 저장, 탭 전환은 클라이언트 캐싱으로 처리.
- 기각 이유: TanStack Query와 상태 관리 역할이 겹쳐 불필요한 복잡도 추가.

### Approach C: 실시간 우선 설계 (사이드/라테럴)
라이브 경기만 별도 엔드포인트로 더 자주 폴링(5초), 스코어 변화 시 펄스 애니메이션 추가.
- 기각 이유: 백엔드에 없는 별도 라이브 엔드포인트를 가정해야 함 — 현재 스코프 밖.

## Recommended Approach
**Approach A.** 백엔드 API가 이미 `range` 파라미터 하나로 세 상태를 명확히 분리해 제공하므로, 탭마다 독립적인 쿼리를 붙이는 것이 가장 자연스럽고 빠르다. 오늘 탭에만 폴링을 걸어 실시간성과 단순함을 동시에 확보한다.

**폴더 구조:**
```
routes/
  index.tsx                 # 탭 쿼리 파라미터 관리 (?range=today 등)
features/matches/
  types.ts                   # Match, Team 타입 (백엔드 스키마 확인 전까지 가정)
  api/useMatches.ts          # TanStack Query, range param
  components/MatchList.tsx
  components/MatchCard.tsx   # 팀 로고 / 이름 / 스코어 / 시리즈 포맷
  components/DateTabs.tsx
  utils/sortMatches.ts       # 라이브 경기 최상단 고정 정렬
components/layout/
  Header.tsx                 # 좌측 로고 + 우측 햄버거 버튼
  HamburgerMenu.tsx
```

**의존성 추가:** `vitest` + `@testing-library/react` + `@testing-library/jest-dom` (테스트, devDependencies). `framer-motion`은 v1 스코프 밖(Next Steps 참고).

## UI 규칙 (와이어프레임 확정, 2026-08-17 / plan-design-review 반영, 2026-08-17)
- 상단 헤더: 좌측 로고, 우측 햄버거 버튼
- 탭: 어제 / 오늘 / 예정 — 활성 탭은 Rausch(`{colors.primary}`) 언더라인
- **기본 선택 탭:** 앱 진입 시 "오늘" 탭이 기본 선택 상태(`?range=today`)로 시작한다. Problem Statement의 핵심 가치(지금 무슨 일이 일어나는지 보기)와 일치하는 자연스러운 기본값.
- **정렬 (오늘 탭):** 라이브 경기가 항상 최상단. 그다음 나머지 경기(종료 + 예정 혼재)는 킥오프 시각 오름차순 — 즉 이미 종료된 경기가 먼저, 그다음 예정 경기 순으로 이어진다. (예: 라이브 → 14:00 종료 경기 → 17:00 예정 경기)
- **정렬 (어제/예정 탭):** 라이브 개념 없음. 어제 탭은 킥오프 시각순, 예정 탭도 킥오프 시각순으로만 정렬.
- **라이브 → 종료 전환:** 폴링으로 라이브 경기가 종료 상태로 바뀌면 최상단에서 시간순 위치로 카드가 이동한다. **v1은 애니메이션 없이 즉시 재배치** — Framer Motion 도입은 v1 스코프 밖(Next Steps 참고). 실사용 중 전환이 잦고 거슬리면 추후 추가.
- **스크롤 위치 보존:** 폴링으로 리스트가 재정렬돼도 현재 뷰포트에 보이는 카드들은 즉시 움직이지 않는다 — 사용자가 새로고침(pull-to-refresh)하거나 탭을 다시 누를 때만 재정렬 적용. 스크롤 중 카드가 갑자기 사라지는 경험을 방지.
- **매치 카드:** 리그명, (라이브인 경우) LIVE 배지, 팀 로고 + 이름 좌우, 중앙에 스코어 + 시리즈 포맷(Bo3/Bo5/Bo7 등)
- **매치 카드 토큰:** `{rounded.md}`(14px), `{component.property-card}`와 동일한 그림자 티어(`rgba(0,0,0,0.02) 0 0 0 1px, rgba(0,0,0,0.04) 0 2px 6px, rgba(0,0,0,0.1) 0 4px 8px`), 내부 패딩 `{spacing.base}`(16px) — DESIGN.md의 기존 카드 컴포넌트 재사용.
- **스코어 타이포:** `{typography.display-md}`(21px/700) — `rating-display`(64px)는 리스팅 페이지 전용 loud 순간이라 리스트에 반복 사용하지 않음.
- **LIVE 배지 스타일:** Rausch 배경(`{colors.primary}`), 흰 텍스트(`{colors.on-primary}`), `{rounded.full}` 필 형태, 작은 동그라미 점 포함 — 와이어프레임 그대로 토큰화.
- **스코어 색상:** 종료된 경기는 패배 팀의 스코어를 회색(`{colors.muted-soft}`)으로 낮춰 승패를 시각적으로 구분. 진행 중(라이브) 경기는 승부가 갈리지 않았으므로 양쪽 동일한 색 유지.
- **취소/연기된 경기:** 승패 판정 로직은 세트 스코어 유무에 의존한다. 세트 스코어가 없는데 킥오프 시각이 과거인 경우, 스코어 자리에 작은 muted 텍스트 배지("취소" 또는 "연기")로 예외 표시 — "상태 라벨 제거" 규칙은 진행/종료/예정에만 적용되고 이 케이스는 예외.
- **상태 라벨 제거:** "종료", "경기 전" 같은 텍스트 배지는 쓰지 않는다 — 스코어 유무/색상 처리와 예정 경기의 킥오프 시간 표시로 상태를 전달. (취소/연기는 예외 — 위 항목 참고)
- 예정 경기 카드는 스코어 대신 시리즈 포맷만 표시, 상단에 킥오프 시각 강조.
- 디자인 토큰은 기존 `DESIGN.md` (Airbnb 계열 시스템) 그대로 재사용.
- **헤더 로고:** 이번 스코프는 "LoL View" 텍스트 워드마크로 처리 (와이어프레임 기준). 별도 이미지 로고 제작은 스코프 밖.
- **폴링 범위:** 오늘 탭만 활성 상태에서 폴링. 어제/예정 탭은 진입 시 1회 fetch로 끝, 폴링 없음.
- **로딩 상태:** 매치 카드 형태 회색 스켈레톤 3개.
- **빈 상태:** 해당 range에 경기가 없으면 "예정된 경기가 없어요" 류의 중앙 정렬 안내 문구.
- **에러 상태:** fetch 실패 시 안내 문구 + 재시도 버튼. 재시도 버튼은 `{component.button-secondary}` 재사용.
- **타임존:** range 경계(어제/오늘/예정 구분)와 킥오프 시각은 KST(Asia/Seoul) 기준으로 가정. 백엔드 응답이 다른 타임존이면 프론트에서 변환.
- **터치 타겟 / 색상 대비:** 햄버거 버튼·탭·재시도 버튼은 44×44px 최소 터치 영역 확보(WCAG AAA 기준). 본문 텍스트는 DESIGN.md 토큰(ink #222222, body #3f3f3f)이 흰 배경에서 이미 4.5:1 이상 대비를 만족.

### v1 스코프 밖 — 반응형/접근성 상세 (TODOS.md 참고)
태블릿(744-1128px)·데스크톱(1128px+) 대응, 키보드 내비게이션 패턴, 스크린리더 ARIA 랜드마크는 이번 스코프에서 다루지 않는다. 모바일(390px) 뷰포트만 확정. DESIGN.md에 이미 3단계 반응형 규칙이 정의돼 있으니, 확장 시 그 규칙을 기준으로 삼는다.

### 정렬 로직 흐름 (오늘 탭)

```
useMatches("today")
      │
      ▼
  matches[]  (라이브 + 종료 + 예정 혼재, 백엔드 응답 순서 불특정)
      │
      ▼
sortMatches(matches, "today")
      │
      ├── isLive === true  ──────────► 최상단 그룹 (여러 건이면 킥오프 시각순)
      │
      └── isLive === false ──────────► 나머지 그룹, kickoffAt 오름차순
                                        (종료 경기 = 과거 시각, 예정 경기 = 미래 시각
                                         → 자연히 종료 먼저, 예정 나중)
      │
      ▼
  [최상단 그룹] + [나머지 그룹]  ──► MatchList 렌더
      │
      ▼ (15초 폴링, refetchInterval)
  라이브 경기가 종료로 전환되면 다음 정렬 계산에서 최상단 → 나머지 그룹으로 이동
      │
      ▼
  v1: 즉시 재배치 (애니메이션 없음). 거슬리면 추후 Framer Motion 등 도입 검토
```

어제/예정 탭은 라이브 개념이 없으므로 `sortMatches`가 단순 `kickoffAt` 오름차순만 적용한다.

## Open Questions
- 팀 로고 이미지 소스(백엔드가 URL을 내려주는지, 프론트에서 별도 매핑이 필요한지) 미확인. 로고 로드 실패 시 이니셜/플레이스홀더로 폴백 필요.
- 폴링 간격 구체값(15초 가정) — 백엔드 rate limit 확인 필요
- 햄버거 메뉴 안에 어떤 항목이 들어가는지 미정 (이번 스코프는 메뉴 트리거 UI까지만)
- API 응답에서 "라이브 여부"를 어떤 필드로 판별하는지 미확인 (`sortMatches.ts`의 최상단 고정 로직이 이 필드에 의존) — 백엔드 응답 스키마 확인 필요
- 같은 시각에 여러 라이브/예정 경기가 겹칠 때의 2차 정렬 기준(리그명 알파벳순 등) 미정 — 낮은 우선순위
- 시리즈 포맷(Bo3/Bo5/Bo7) 필드가 백엔드 응답에 실제로 존재하는지 미확인 — "라이브 여부" 필드와 함께 백엔드 응답 스키마 확인 시 같이 검증 필요
- 취소/연기된 경기를 API가 어떤 값으로 내려주는지, UI에서 어떻게 표기할지(예: "취소됨" 배지 또는 카드 자체 숨김) 미정

## Success Criteria
- 어제/오늘/예정 세 탭이 각각 올바른 range로 데이터를 불러온다
- 오늘 탭에서 라이브 경기가 항상 최상단에 고정되고, 그 아래는 종료·예정 경기가 킥오프 시각순으로 이어진다
- 라이브 경기가 종료로 전환될 때 카드가 튀지 않고 부드럽게 재배치된다
- 매치 카드에서 팀 로고, 이름, 스코어, 시리즈 포맷을 한눈에 확인할 수 있다
- 종료된 경기는 패배 팀 스코어가 시각적으로 구분된다
- 모바일 뷰포트에서 자연스럽게 보인다 (390px 기준 확인됨)
- 경기가 없는 range, fetch 실패, 로딩 중 상태가 각각 명확히 구분되어 표시된다

## API 응답 타입 (가정 — Next Steps 0.5에서 실제 확인 후 갱신 예정)
백엔드 스키마가 아직 미확인이므로 아래는 **임시 가정**이다. Next Steps 0.5(`GET /matches?range=today` 실제 호출)를 거치기 전까지는 이 타입으로 구현을 시작하지 않는다 — `features/matches/types.ts`에 위치할 최종 타입은 실제 응답에 맞춰 다시 작성된다.

```typescript
interface Match {
  id: string;
  league: string;              // 예: "LCK", "LPL"
  teams: [Team, Team];
  seriesFormat?: string;       // 예: "Bo3", "Bo5" — 실제 필드명/존재 여부 미확인
  kickoffAt: string;           // ISO 8601, KST 가정
  isLive: boolean;             // 실제 필드명 미확인 — status enum일 수도 있음
  score?: [number, number];    // 라이브/종료 시에만 존재. 예정 경기는 undefined
  status?: "scheduled" | "live" | "finished" | "cancelled"; // "cancelled" 포함 여부는 미확인 — Open Questions 참고, 확정적으로 넣지 말 것
}

interface Team {
  id: string;
  name: string;
  logoUrl?: string;            // 없으면 이니셜 폴백
}
```
